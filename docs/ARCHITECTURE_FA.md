# معماری و ساختار پروژه

## پشته فناوری

| بخش | انتخاب | دلیل سازگاری با هاست اشتراکی |
|---|---|---|
| زمان اجرا | Node.js 18.18+ (TypeScript → JavaScript) | پشتیبانی Setup Node.js App در cPanel |
| وب فریم‌ورک | Express 5 | اجرای سبک زیر Phusion Passenger، بدون نیاز به کامپایل |
| پایگاه داده | MySQL / MariaDB با `mysql2` | درایور خالص JavaScript؛ بدون ماژول بومی |
| اعتبارسنجی | `zod` | خالص JavaScript و وابستگی کم |
| امنیت HTTP | `helmet` | تنظیم CSP، HSTS، و سایر هدرها |
| رمز عبور | `crypto.scrypt` (داخلی Node.js) | بدون `bcrypt` بومی |
| نمودارها (آینده) | Chart.js (فایل‌های آماده در `public/`) | بدون نیاز به build در هاست |

## لایه‌ها

```
public/            رابط کاربری استاتیک (CSS، JS، فونت) — بدون مرحله build
app.js             نقطه ورود cPanel (Application startup file)
src/
  config/          بارگذاری و اعتبارسنجی تنظیمات محیطی (.env اختیاری)
  db/              اتصال پایگاه داده، تراکنش، migration runner
  lib/             ابزارهای خالص: رمز، تاریخ شمسی، اعداد فارسی، پول، CSV، پاک‌سازی لاگ
  rbac/            کاتالوگ مجوزها و قواعد ضد افزایش دسترسی
  settings/        ثبت مرکزی تنظیمات با نوع، اعتبارسنجی و پیش‌فرض
  modules/         منطق کسب‌وکار به‌تفکیک ماژول (auth, users, roles, settings, audit, install, system, dashboard)
  http/            میان‌افزارها (CSRF، نشست، مجوز، خطا) و ابزارهای نمایش
  routes/          مسیرهای HTTP (فقط هماهنگ‌کننده؛ منطق داخل سرویس‌ها)
  views/           قالب‌های HTML با escape خودکار
  bootstrap.ts     ترکیب وابستگی‌ها (تنها نقطه اتصال سرویس‌ها)
migrations/        mysql/ و sqlite/ (هر دو NNN_name.sql؛ هر فایل فقط یک‌بار اجرا می‌شود، با checksum)
dist/              خروجی کامپایل‌شده (در ZIP نسخه انتشار قرار دارد)
```

## امنیت در معماری

- **نشست:** توکن تصادفی ۲۵۶ بیتی در کوکی `sid` (HttpOnly، SameSite=Lax، Secure در HTTPS). فقط هش SHA-256 توکن در پایگاه داده ذخیره می‌شود.
- **CSRF:** روش double-submit با کوکی `csrf` و فیلد `_csrf` در هر فرم POST.
- **مجوز:** `requirePermission` در سمت سرور، با خواندن زنده مجوزها از پایگاه داده در هر درخواست.
- **ورود:** پیام خطای یکسان، هش‌کردن زمان‌بندی برای کاربر ناموجود، و محدودیت تلاش در پایگاه داده.
- **خطاها:** پیام‌های عمومی فارسی برای کاربر؛ جزئیات فقط در لاگ (بدون رمز، کوکی یا کلید).
- **HTML:** همه متغیرها با escape خودکار درج می‌شوند؛ CSP بدون `unsafe-inline`.
- **فایل‌ها:** پوشه `storage/` خارج از مسیرهای استاتیک است و فقط از طریق برنامه قابل دسترسی است.

## پایگاه داده (نسخه ۰۰۱)

| جدول | کاربرد | نکات |
|---|---|---|
| `schema_migrations` | سابقه migration ها | نسخه، نام، checksum، زمان اجرا |
| `settings` | تنظیمات (کلید/مقدار JSON) | فقط کلیدهای ثبت‌شده در registry پذیرفته می‌شوند |
| `roles` | نقش‌ها | `slug` یکتا، `is_system`، `is_active` |
| `permissions` | کاتالوگ مجوزها | `code` یکتا، `module` |
| `role_permissions` | ارتباط نقش و مجوز | کلید مرکب |
| `users` | کاربران | `username`، `email`، `phone` یکتا؛ `role_id` با `ON DELETE RESTRICT` |
| `sessions` | نشست‌ها | هش توکن؛ انقضا و ابطال |
| `audit_logs` | رویدادهای حسابرسی | بدون رمز یا کلید؛ ایندکس زمان، کاربر، رویداد |
| `login_attempts` | تلاش‌های ورود | هش شناسه و IP؛ برای محدودسازی نرخ |

زمان‌ها در پایگاه داده به‌صورت UTC ذخیره می‌شوند و فقط در لایه نمایش به منطقه زمانی تهران و تقویم شمسی تبدیل می‌شوند. مبالغ مالی (در آینده) به‌صورت عدد صحیح ریال در BIGINT ذخیره خواهند شد.

## افزودن ماژول جدید

1. مجوزهای جدید را به `src/rbac/permissions.ts` اضافه کنید (با الگوی `بخش.عملیات`).
2. فایل migration جدید با شماره بعدی را در **هر دو** پوشه `migrations/mysql/` و `migrations/sqlite/` بسازید (هرگز فایل قبلی را ویرایش نکنید).
3. سرویس منطق کسب‌وکار را در `src/modules/<name>/` بسازید و فقط به سرویس‌های لازم از طریق `AppServices` وابسته شوید.
4. مسیرها را در `src/routes/` اضافه کنید و هر مسیر را با `requirePermission` محافظت کنید.
5. ماژول را در `src/modules/registry.ts` ثبت کنید تا در صفحه سلامت سامانه دیده شود.
6. تست واحد و در صورت نیاز تست یکپارچه‌سازی بنویسید.
