# راهنمای نصب روی هاست cPanel (بدون SSH)

> **پیش‌نیاز قطعی:** هاست باید امکان **Setup Node.js App** را در cPanel داشته باشد (نسخه Node.js ۱۸.۱۸ یا بالاتر).
> اگر این امکان در هاست شما وجود ندارد، این نرم‌افزار قابل اجرا نیست و باید هاست دیگری (یا VPS) انتخاب شود.
> نام دقیق دکمه‌ها ممکن است بسته به نسخه cPanel و ارائه‌دهنده کمی متفاوت باشد.

## ۱. آماده‌سازی فایل نصب

1. روی کامپیوتر خود فایل `myclass-<version>.zip` را از بخش انتشار (Release) دریافت کنید.
2. (توصیه) مطمئن شوید فایل ZIP شامل پوشه‌های `dist/`، `migrations/`، `public/`، فایل `app.js` و `package.json` است.

## ۲. انتخاب پایگاه داده

برنامه دو نوع پایگاه داده را پشتیبانی می‌کند. نوع آن را در فرم نصب (مرحله ۵) انتخاب می‌کنید:

- **SQLite (پیشنهادی برای میزبانی ساده):** نیازی به ساخت پایگاه داده در cPanel نیست. فایل پایگاه داده در پوشه `storage/app.sqlite` (یا مسیر `SQLITE_PATH`) ساخته می‌شود. **پوشه `storage` باید قابل نوشتن باشد و خارج از `public_html` قرار داشته باشد.** مناسب مؤسسات کوچک و متوسط؛ کل پایگاه داده در حافظه بارگذاری می‌شود و فقط یک فرایند Node.js باید از آن استفاده کند (در cPanel معمولاً همین است).
- **MySQL / MariaDB:** برای مؤسسات بزرگ‌تر یا وقتی هاست شما سرویس MySQL دارد. مراحل زیر را انجام دهید.

اگر SQLite را انتخاب می‌کنید، بخش‌های «ساخت پایگاه داده MySQL» و متغیرهای `DB_*` لازم نیستند و می‌توانید به مرحله ۳ بروید.

### ساخت پایگاه داده MySQL (فقط در صورت انتخاب MySQL)

1. در cPanel بخش **MySQL® Databases** را باز کنید.
2. یک پایگاه داده بسازید، مثلاً `cpuser_myclass` (cPanel پیشوند نام کاربری را خودکار اضافه می‌کند؛ نام کامل را یادداشت کنید).
3. یک کاربر MySQL با رمز عبور **قوی** بسازید.
4. کاربر را به پایگاه داده اضافه کنید و گزینه **ALL PRIVILEGES** را انتخاب کنید.
5. نام پایگاه داده، نام کاربر، رمز عبور و نشانی سرور (معمولاً `localhost`) را در جایی امن نگه دارید. **این اطلاعات را در فایل‌های عمومی یا چت ذخیره نکنید.**

## ۳. بارگذاری فایل‌ها

1. در **File Manager** یک پوشه خارج از `public_html` بسازید، مثلاً `/home/<user>/myclass`.
   **مهم:** پوشه برنامه نباید داخل `public_html` باشد تا فایل‌های سورس و تنظیمات، مستقیماً قابل دانلود نباشند.
2. فایل ZIP را در همین پوشه بارگذاری (Upload) و سپس **Extract** کنید.
3. ساختار باید به این شکل باشد: `app.js` و `package.json` و `dist/` و `migrations/` و `public/` در ریشه پوشه برنامه.

## ۴. ایجاد برنامه Node.js

1. در cPanel بخش **Setup Node.js App** را باز کنید و **Create Application** را بزنید.
2. تنظیمات:
   - **Node.js version:** ۱۸ یا بالاتر (توصیه: ۲۰ یا ۲۲).
   - **Application mode:** Production
   - **Application root:** مسیر پوشه برنامه (مثلاً `myclass`)
   - **Application URL:** دامنه یا زیردامنه‌ای که می‌خواهید برنامه روی آن باشد.
   - **Application startup file:** `app.js`
3. بخش **Environment variables** را باز کنید و متغیرهای زیر را اضافه کنید (مقادیر را خودتان وارد کنید):

| نام متغیر | توضیح |
|---|---|
| `NODE_ENV` | `production` |
| `DB_DRIVER` | (اختیاری) `sqlite` یا `mysql`. اگر خالی بماند، انتخاب در فرم نصب انجام می‌شود. |
| `SQLITE_PATH` | (اختیاری، فقط SQLite) مسیر فایل پایگاه داده؛ پیش‌فرض `storage/app.sqlite` |
| `DB_HOST` | (فقط MySQL) معمولاً `localhost` |
| `DB_PORT` | (فقط MySQL) `3306` |
| `DB_NAME` | (فقط MySQL) نام کامل پایگاه داده (با پیشوند cPanel) |
| `DB_USER` | (فقط MySQL) نام کامل کاربر MySQL |
| `DB_PASSWORD` | (فقط MySQL) رمز عبور کاربر MySQL |
| `INSTALL_TOKEN` | یک رشته تصادفی حداقل ۲۴ نویسه (مثلاً از یک مولد رمز عبور) — **فقط برای نصب** |
| `COOKIE_SECURE` | `true` (پس از فعال‌سازی SSL) |
| `TRUST_PROXY` | `1` |
| `SESSION_TTL_HOURS` | `8` (اختیاری) |
| `STORAGE_DIR` | (اختیاری) مسیر مطلق پوشه خصوصی؛ در صورت خالی‌بودن `storage/` داخل پوشه برنامه ساخته می‌شود |

4. **Save** را بزنید. سپس دکمه **Run NPM Install** را بزنید تا وابستگی‌ها نصب شوند. (اگر این دکمه وجود نداشت، از بخش «روش جایگزین نصب وابستگی‌ها» استفاده کنید.)
5. دکمه **Restart** را بزنید.

## ۵. اجرای نصب تحت وب

1. نشانی برنامه را باز کنید؛ به‌صورت خودکار به `/install` هدایت می‌شوید.
2. بخش «بررسی سازگاری محیط» را ببینید. هر مورد خطا باید برطرف شود:
   - توکن نصب: `INSTALL_TOKEN` باید تنظیم شده باشد.
   - پوشه `storage`: مجوز پوشه را در File Manager بررسی کنید (معمولاً 755).
   - تنظیمات MySQL و وضعیت اتصال، هشدار هستند و فقط زمانی مهم‌اند که MySQL را انتخاب کنید.
3. **نوع پایگاه داده** را انتخاب کنید: SQLite یا MySQL / MariaDB.
4. فرم را کامل کنید: توکن نصب، نام مؤسسه، مشخصات مدیر اصلی و رمز عبور قوی (حداقل ۱۰ نویسه).
5. **نصب سامانه** را بزنید. برنامه ابتدا به پایگاه داده انتخابی وصل می‌شود؛ اگر اتصال برقرار نشود، نصب متوقف می‌شود و هیچ تنظیمی ذخیره نمی‌شود. پس از اتصال موفق، جداول ساخته و حساب مدیر اصلی تعریف می‌شود.
6. نوع انتخاب‌شده در فایل `storage/db-config.json` ذخیره می‌شود (بدون رمز عبور). پس از نصب، نوع پایگاه داده از همین فایل خوانده می‌شود. **تغییر نوع پایگاه داده پس از نصب پشتیبانی نمی‌شود**؛ برای انتقال داده باید با مدیر فنی هماهنگ کنید.
7. پس از نصب موفق، صفحه `/install` به‌صورت دائمی غیرفعال می‌شود (فایل `storage/install.lock` ساخته می‌شود).

## ۶. تنظیمات پس از نصب (امنیت)

1. در Setup Node.js App متغیر **`INSTALL_TOKEN` را حذف کنید** و برنامه را Restart کنید.
2. SSL (Let's Encrypt یا SSL رایگان cPanel) را برای دامنه فعال کنید و `COOKIE_SECURE=true` را تنظیم کنید.
3. از بخش **سلامت سامانه** وضعیت اتصال، migration ها و هشدارها را بررسی کنید.
4. از بخش **تنظیمات > اطلاعات مؤسسه** نام، تماس، نشانی و رنگ‌های سازمان را وارد کنید.

## روش جایگزین نصب وابستگی‌ها (بدون دکمه Run NPM Install)

بسته ZIP نسخه انتشار شامل پوشه `node_modules` (فقط وابستگی‌های اجرایی و خالص JavaScript) است؛ پس نیازی به کامپایل بومی یا SSH نیست. اگر از نسخه‌ای استفاده می‌کنید که `node_modules` ندارد، نسخه انتشار رسمی را دریافت کنید.

## عیب‌یابی سریع

| پیام / علامت | علت احتمالی و اقدام |
|---|---|
| صفحه «راه‌اندازی برنامه ناموفق بود» | پوشه `dist/` وجود ندارد یا `npm run build` اجرا نشده. نسخه انتشار را دوباره بارگذاری کنید. |
| خطای ۵۰۰ / «خطای داخلی» | لاگ برنامه را در Setup Node.js App بررسی کنید؛ علت دقیق فقط در لاگ ثبت می‌شود. |
| «توکن نصب نادرست است» | مقدار `INSTALL_TOKEN` و ورودی فرم را مقایسه کنید. |
| «اتصال به MySQL برقرار نشد» | `DB_HOST`، نام کامل پایگاه داده و کاربر (با پیشوند cPanel) و رمز را بررسی کنید. |
| «اتصال به SQLite برقرار نشد» | پوشه `storage` قابل نوشتن نیست یا فایل پایگاه داده قفل است. مجوز پوشه و `SQLITE_PATH` را بررسی کنید. |
| صفحه ورود کار نمی‌کند و مدام برمی‌گردد | `COOKIE_SECURE=true` بدون SSL باعث می‌شود مرورگر کوکی را ذخیره نکند؛ SSL را فعال کنید یا موقتاً `false` بگذارید. |
| بعد از به‌روزرسانی، هشدار migration نمایش داده می‌شود | از بخش سلامت سامانه با مجوز «اجرای migration» آن را اجرا کنید (ابتدا پشتیبان بگیرید؛ [راهنمای پشتیبان‌گیری](BACKUP_RESTORE_FA.md)). |
