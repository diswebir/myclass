# تصمیم‌گیری معماری: تولید مدارک و خروجی PDF فارسی (Phase 0 Spike)

## پیش‌زمینه و محدودیت‌ها
طبق بخش‌های ۲ و ۳ مستند حاکم (`MASTER_SPEC.md`):
1. اجرای Puppeteer / Headless Chromium در هاست‌های اشتراکی cPanel به دلیل محدودیت شدید حافظه، نبود کتابخانه‌های گرافیکی سیستمی (libnss, libgbm) و ممنوعیت باینری‌های سنگین به صورت قطعی غیرممکن است.
2. کتابخانه‌هایی مانند `pdfmake` و `pdf-lib` فاقد موتور داخلی پیشرفته BiDi و الحاق حروف فارسی (Ligature shaping) هستند و کلمات فارسی را بدون شکل‌دهی وارونه یا گسسته رندر می‌کنند مگر اینکه فرآیند شکل‌دهی متن (Text Reshaping) و دوجهته (BiDi) روی آن اعمال شود.

## تحلیل گزینه‌ها
- **گزینه الف (رندر سرور با موتور شکل‌دهی متن):** استفاده از شکل‌دهی کاراکترهای عربی/فارسی (Arabic/Persian glyph reshaping) و تبدیل ترتیب بصری حروف + embed کردن فونت TTF استاندارد فارسی (مانند فونت Vazirmatn).
- **گزینه ب (قالب چاپی و گواهی تعاملی HTML/CSS Print-Optimized):** طراحی دقیق گواهی با CSS Print (`@page { size: A4 landscape; margin: 0; }`)، سربرگ، مهر، امضا، بارکد QR معتبر و دکمه چاپی «چاپ / ذخیره به عنوان PDF» در مرورگر که از فونت‌های استاندارد تعبیه‌شده بدون هرگونه شکستگی حروف استفاده می‌کند.

## تصمیم نهایی
سامانه از **یک معماری هیبریدی مقاوم** استفاده می‌کند:
1. **قالب استاندارد چاپی وب:** برای بالاترین کیفیت گرافیکی، دقت رنگ و نمایش بی‌نقص فونت وزیرمتن فارسی، یک مسیر نمایش اختصاصی `/certificates/print/:code` و `/verify/:code` به همراه دکمه چاپ مستقیم و استایل‌های `@media print` فراهم می‌شود.
2. **تولیدکننده PDF سمت سرور خالص:** با ترکیب شکل‌دهنده حروف فارسی و فونت TTF جهت دانلود مستقیم فایل PDF برای سناریوهایی که نیاز به دانلود خودکار دارند.
3. در هر دو حالت، شناسه یکتای مدرک، QR Code اعتبارسنجی زنده، مهر و امضای دیجیتالی تعبیه می‌شود.
