# پشتیبان‌گیری، بازیابی و به‌روزرسانی

## پشتیبان‌گیری از پایگاه داده (بدون SSH)

1. در cPanel بخش **Backup** یا **phpMyAdmin** را باز کنید.
2. **Backup** → **Download a MySQL Database Backup** را انتخاب کنید و پایگاه داده برنامه را دانلود کنید.
   (در phpMyAdmin: پایگاه داده را انتخاب کنید → Export → Quick → SQL.)
3. فایل `.sql.gz` را در مکانی امن (خارج از `public_html`) نگهداری کنید. فایل شامل رمزهای هش‌شده کاربران و اطلاعات مؤسسه است؛ آن را به اشتراک نگذارید.
4. پشتیبان را در تاریخ مشخص نام‌گذاری کنید، مثلاً `myclass-db-1405-07-17.sql.gz`.

## پشتیبان‌گیری از فایل‌ها

- پوشه `storage/` (شامل `install.lock` و در آینده فایل‌های آپلودی خصوصی) و پوشه برنامه را از File Manager یا بخش Backup دانلود کنید.
- فایل `.env` یا تنظیمات Environment variables را جداگانه و امن ذخیره کنید؛ **این اطلاعات در ZIP پشتیبان قرار نمی‌گیرند.**

## بازیابی

> بازیابی **فقط** توسط مدیر فنی یا مدیر اصلی انجام شود و پیش از آن پشتیبان فعلی گرفته شود.

1. برنامه را از Setup Node.js App متوقف کنید (Stop).
2. در phpMyAdmin پایگاه داده مقصد را خالی کنید (Drop tables) یا پایگاه داده جدید بسازید.
3. فایل SQL را Import کنید.
4. برنامه را Start/Restart کنید و از بخش سلامت سامانه، وضعیت migration ها و اتصال را بررسی کنید.
5. ثبت بازیابی: پس از بازیابی موفق، یادداشت کنید چه نسخه‌ای و چه زمانی بازیابی شده است.

## به‌روزرسانی نسخه و اجرای migration

1. **حتماً** پشتیبان پایگاه داده بگیرید.
2. فایل‌های نسخه جدید را جایگزین کنید (پوشه‌های `dist/`، `public/`، `migrations/`، `app.js`، `package.json`). فایل `storage/install.lock` و `.env` را **حذف نکنید**.
3. در صورت تغییر وابستگی‌ها، **Run NPM Install** را بزنید و سپس Restart کنید.
4. وارد سامانه شوید، به **سلامت سامانه** بروید و اگر migration در انتظار است، دکمه **اجرای migration** را بزنید.
5. migration ها به ترتیب شماره اجرا می‌شوند و هر کدام فقط یک‌بار ثبت می‌شود؛ اگر محتوای یک فایل migration که قبلاً اجرا شده تغییر کرده باشد، سامانه اجرای migration را متوقف می‌کند.
6. نتیجه در سوابق رویدادها ثبت می‌شود.

## محدودیت‌های مهم

- MySQL دستورات DDL (ساخت/تغییر جدول) را به‌صورت خودکار commit می‌کند؛ بنابراین اگر migration وسط کار متوقف شود، ممکن است بخشی از تغییرات اعمال شده باشد. برای همین پیش از هر migration پشتیبان الزامی است.
- پشتیبان فایل‌های آپلودی هنوز به‌صورت خودکار در برنامه ساخته نمی‌شود (در بخش‌های بعدی پروژه).
