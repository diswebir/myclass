# معماری تفصیلی سیستم (System Architecture)

## ۱. ساختار ماژولار و لایه‌بندی
سیستم با تفکیک کامل مسئولیت‌ها (Separation of Concerns) و معماری لایه‌ای پیاده‌سازی شده است:

```
src/
├── core/                       # زیرساخت بنیادین و مشترک
│   ├── config.ts               # تنظیمات سیستمی و متغیرهای محیطی با Zod
│   ├── db.ts                   # اتصال پایگاه داده، درایور mysql2 و Kysely
│   ├── errors.ts               # سلسله‌مراتب خطاهای برنامه و مدیریت یکپارچه خطاها
│   ├── logger.ts               # لاگ‌گیری ساختاریافته بدون نشت اطلاعات محرمانه
│   ├── security.ts             # هدرها، CSRF، اعتبارسنجی توکن، Sanitization
│   ├── policy.ts               # لایه مرکزی سیاست‌گذاری دسترسی به داده‌ها ( ضد IDOR)
│   ├── view-engine.ts          # رندر صفحات EJS با توابع کمکی تاریخ شمسی و مبالغ
│   └── types.ts                # تعاریف تایپ‌های مشترک کل سامانه
│
├── modules/                    # ماژول‌های مستقل نرم‌افزار
│   ├── installer/              # نصب‌کننده تحت وب، بررسی پیش‌نیازها و قفل نصب
│   ├── health/                 # مانیتورینگ سلامت سامانه، دیتابیس و حافظه
│   ├── auth/                   # احراز هویت، ورود، خروج، نشست‌ها
│   ├── rbac/                   # مدیریت نقش‌ها و ماتریس دسترسی‌ها
│   ├── users/                  # کاربران سیستم و تغییر کلمات عبور
│   ├── settings/               # تنظیمات عمومی، هویت بصری و مالی
│   ├── audit/                  # ثبت وقایع امنیتی و گزارش عملکرد
│   ├── files/                  # مدیریت و بارگذاری امن فایل‌ها
│   ├── teachers/               # مدیریت اساتید و پرونده‌های آموزشی
│   ├── students/               # پرونده فراگیران و ورود گروهی CSV
│   ├── courses/                # دوره‌ها و کلاس‌های آموزشی
│   ├── sessions/               # جلسات کلاس‌ها و تشخیص تداخل زمانی
│   ├── preregistration/        # فرم‌های عمومی پیش‌ثبت‌نام و کد پیگیری
│   ├── enrollment/             # فرآیند نهایی‌سازی ثبت‌نام
│   ├── attendance/             # حضور و غیاب کلاسی و محاسبات درصد
│   ├── finance/                # شهریه، اقساط، فیش‌های کارت‌به‌کارت و دفتر کل
│   ├── certificates/           # صدور مدرک، اعتبارسنجی عمومی و بارکد QR
│   ├── sms/                    # آداپتور IPPanel Edge، نگاشت متغیرها و صف پیامک
│   ├── dashboard/              # داشبورد تحلیلی و نمودارهای Chart.js
│   ├── backup/                 # تهیه نسخه پشتیبان دیتابیس بدون ابزار سیستمی
│   └── modules-registry/       # رجیستری و مانیفست وضعیت ماژول‌ها
│
├── jobs/                       # اسکریپت‌های اجرایی Cron Jobs
│   └── run.ts                  # پردازشگر صف پیامک و بررسی سررسید اقساط
│
├── ui/                         # فایل‌های ظاهری و صفحات SSR
│   ├── views/                  # قالب‌های EJS به تفکیک ماژول‌ها
│   │   ├── layouts/            # سربرگ، پانوشت و قاب اصلی RTL
│   │   ├── auth/
│   │   ├── admin/
│   │   ├── teacher/
│   │   ├── student/
│   │   └── public/             # صفحات عمومی: استعلام مدرک، پیش‌ثبت‌نام
│   └── assets/                 # فونت وزیرمتن، Chart.js، استایل‌ها و اسکریپت‌ها
│
├── server.ts                   # راه‌انداز اصلی سرور Express
└── app.ts                      # تنظیم میان‌افزارها، مسیرها و مدیریت خطاها
```

## ۲. لایه کنترل دسترسی به داده‌ها (Data Policy Layer)
برای جلوگیری قطعی از حملات IDOR:
- هیچ شناسه رکوردی در کنترلر مستقیماً بدون ارزیابی سیاست مالکیت خوانده یا ویرایش نمی‌شود.
- کلاس `DataPolicy` متدهایی دارد مانند:
  - `canAccessClass(userId, role, classId)`
  - `canAccessStudentData(userId, role, studentId)`
  - `canAccessEnrollment(userId, role, enrollmentId)`
  - `canReviewPayment(userId, role, paymentId)`
- اساتید فقط اجازه مشاهده و مدیریت کلاس‌های تخصیص‌یافته به خود را دارند.
- دانشجویان منحصراً به اطلاعات ثبت‌نام، مالی، حضور و مدرک صادرشده برای خود دسترسی دارند.

## ۳. سازگاری cPanel و اجرای بدون SSH
1. **نقطه ورود Phusion Passenger:**
   فایل `app.js` در ریشه پروژه قرار دارد و ترافیک را به ماژول کامپایل‌شده `dist/server.js` منتقل می‌کند.
2. **بدون وابستگی Native:**
   استفاده از `bcryptjs` (Pure JS) به جای `bcrypt`/`argon2`.
   استفاده از `mysql2` (Pure JS) بدون نیاز به کامپایلر C++ در هاست اشتراکی.
3. **نصب‌کننده تحت وب (`/install`):**
   - سازگاری محیط (نسخه Node، دسترسی نوشتن پوشه `storage/`، اتصال دیتابیس) را می‌سنجد.
   - Migrationها را گام‌به‌گام اجرا می‌کند.
   - حساب مدیر اول را می‌سازد.
   - فایل قفل `storage/installed.lock` را ثبت می‌کند و دسترسی مجدد به نصب‌کننده را مسدود می‌سازد.
4. **فایل SQL پشتیبان:**
   فایل `database.sql` آماده داخل بسته قرار می‌گیرد تا اگر کاربری ترجیح داد از phpMyAdmin برای واردسازی جداول استفاده کند، کاملاً مستقل امکان‌پذیر باشد.
5. **کران‌جاب اختصاصی:**
   - اسکریپت `node dist/jobs/run.js` یا فراخوانی وب‌هوک با کلید امنیتی:
     `GET /api/cron/process?token=CRON_SECRET`
